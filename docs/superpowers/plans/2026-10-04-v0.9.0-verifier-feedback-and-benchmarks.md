# v0.9.0 Verifier Feedback Loop + Benchmark Suite Implementation Plan

> **For agentic workers:** Implement task-by-task. Spec: `docs/v0.9.0-kimi-task-brief.md` (the v0.9.0 开发任务书). Steps use checkbox (`- [ ]`) syntax.

**Goal:** Feed verifier findings (TS type errors, API-surface breaks) back into the tier-4 fix loop, and add a reproducible benchmark suite that measures upgrade-fix accuracy.

**Architecture:** Task A adds a `verifyEnhanced` callback to `runFixLoop` (src/agent/fixer.ts); run.ts builds it from the existing `runStaticAnalysis` + `analyzeApiChanges` and passes it in. Task B adds `src/benchmarks/run.ts` (compiles to `dist/benchmarks/run.js`) driving real `run()` calls against minimal fixture repos in `benchmarks/cases/`.

**Tech Stack:** TypeScript ESM, tsc → dist/, node:test, commander.

## Global Constraints

- Reuse `maxRounds` / `maxTokens` — NO new budget variables.
- Do NOT feed back: suspicious changes, new-`any`, ESLint warnings, sandbox, perf.
- Do NOT touch tier 1-3 logic.
- Any `src/` change referenced by the action requires `npm run build:action` and committing `action-dist/index.cjs`.
- Tests: node:test + assert/strict; isolate cache/stats via `GREENBUMP_CACHE_DIR` / `GREENBUMP_STATS_DIR` (see `src/agent/fixer.test.ts` `withTmpDir`).
- `npm test` (191 tests) must stay green.

## Documented deviations from the spec (with reasons)

1. `verifyEnhanced` signature is `(cwd: string, editedFiles: string[]) => Promise<EnhancedVerification>` — the spec's own report builder needs `fix.editedFiles`, but `FixResult` doesn't exist mid-loop; the loop passes its live `llmEditedFiles`.
2. Benchmark runner lives at `src/benchmarks/run.ts` (not `benchmarks/run.ts`): tsconfig has `rootDir: "src"`, and the spec's npm scripts require `dist/benchmarks/run.js`. Fixtures + README stay in top-level `benchmarks/`.
3. `forbiddenFileChanges` is checked against `summary.editedFiles` (agent edits), not the full git diff — the upgrade itself legitimately rewrites package.json/lockfile, so a diff-based check would false-positive on every case. This still catches "AI edited a test file".
4. A.4's "run.ts 层测试" is implemented as (a) unit tests for the exported `runEnhancedVerification` from run.ts and (b) a fixer-loop integration test wiring run.ts's real callback with a stub provider asserting `enhancedRounds > 0`. A full `run()` e2e in unit tests would require the npm registry; that coverage comes from the manual e2e + the benchmark itself.
5. New `RunOptions.fixProvider?: Provider` injection point (needed by benchmark no-key mode and tests; `RunOptions.provider` stays the preset-name string).

## Review Focus

- Identical verifier report twice → loop must exit early (`enhancedStuck`), needsReview=true, never infinite-loop.
- Enhanced feedback on the last allowed round → no extra round stolen; run ends, post-checks still flag review.
- `run_check` pass via the "model stopped without tool calls" exit → enhanced verification must run there too, not only on the tool-call path.
- Tier 1-3 fixes (early `tierResult` returns) must never invoke `verifyEnhanced`.
- Benchmark fixture with no API key: LLM-tier cases SKIP cleanly, exit code stays 0.

### Task 1: fixer.ts — EnhancedVerification + loop integration

**Files:**
- Modify: `src/agent/fixer.ts`
- Test: `src/agent/fixer.test.ts`

**Interfaces:**
- Produces:
  - `interface EnhancedVerification { hasIssues: boolean; report: string; summary: string }`
  - `FixOptions.verifyEnhanced?: (cwd: string, editedFiles: string[]) => Promise<EnhancedVerification>`
  - `FixResult.enhancedRounds: number` (0 for tier 1-3 results)
  - `FixResult.enhancedStuck?: boolean` (same report twice → gave up)

- [ ] **Step 1: Write 4 failing tests in fixer.test.ts**
  1. base check passes + `verifyEnhanced` → `{hasIssues:false}` → fixed:true, rounds:1, enhancedRounds:0, provider called once.
  2. `verifyEnhanced` returns issues once then clean → fixed:true, rounds:2, enhancedRounds:1; assert `provider.calls[1]` last message role "user" contains the report text ("Property 'del' does not exist").
  3. `verifyEnhanced` returns the identical report every time → loop exits before maxRounds, `enhancedStuck === true`, `enhancedRounds === 1`, fixed:true.
  4. no `verifyEnhanced` → existing behavior (covered by existing tests; add explicit assertion `enhancedRounds === 0`).
- [ ] **Step 2: Run tests, confirm 1-3 fail** (`npm run build && cd dist && node --test agent/fixer.test.js`)
- [ ] **Step 3: Implement in fixer.ts**
  - Add the interfaces. In `runFixLoop` tier-4: `const seenReports = new Set<string>(); let enhancedRounds = 0; let enhancedStuck = false;`
  - Local async fn `enhancedFeedback(round)`: returns "continue" | "stop". No callback → "stop". Calls `opts.verifyEnhanced(opts.cwd, [...llmEditedFiles])`; clean → "stop"; sha256(report) already in `seenReports` → set enhancedStuck, log, "stop"; `round >= opts.maxRounds` → "stop" (post-checks in run.ts will flag); else `seenReports.add(hash)`, `enhancedRounds++`, log, push user message `Build and tests pass, but additional verification found problems that must be fixed:\n\n${report}\n\nFix these without breaking the build/tests.`, return "continue".
  - Call it at both success exits: the `run_check` pass break (`if (fixed)`) and the no-toolCalls final-check exit (`fixed = r.ok`). On "continue": `fixed = false; continue;`.
  - `tierResult` gains `enhancedRounds: 0`. Final return gains `enhancedRounds`, `enhancedStuck: enhancedStuck || undefined`.
- [ ] **Step 4: Tests pass; full `npm test` green**

### Task 5: Benchmark runner (src/benchmarks/run.ts)

**Files:** Create `src/benchmarks/run.ts`

**Interfaces:**
- case.json: `{ name, dep, from, to, ecosystem, description, expectedTier }`
- expect.json: `{ shouldFix: boolean, neededFix?: boolean, forbiddenPatterns?: string[], requiredPatterns?: string[], forbiddenFileChanges?: string[] }`

- [ ] **Step 1: Implement runner**
  - Cases dir: `fileURLToPath(new URL("../../benchmarks/cases", import.meta.url))`.
  - Args (hand-rolled): `--case <name>`, `--no-llm`, `--json`, `--verbose`.
  - Isolation per run: `GREENBUMP_CACHE_DIR`/`GREENBUMP_STATS_DIR` = fresh mkdtemp (set at process start).
  - Per case: `fs.cp` repo → mkdtemp; `npm install --no-audit --no-fund` (execFile); `git init -q && git add -A && git -c user.email=bench@gb -c user.name=bench commit -qm init`; `run({ cwd, dep, to: case.to, maxRounds: 15, fixProvider: noLlm ? stubProvider : undefined, onLog })`. `stubProvider`: name "bench-stub", returns `{ text: "", toolCalls: [] }` — if the LLM loop is reached in --no-llm mode the case fails honestly.
  - `--no-llm` OR no key (`hasAnyKey()` false) → skip cases with `expectedTier >= 4`, row = SKIP.
  - Evaluate: `summary.fixed === expect.shouldFix`; `expect.neededFix !== undefined && summary.neededFix === expect.neededFix`; patterns tested against final contents of `summary.editedFiles`; `forbiddenFileChanges` (glob-ish: `**/*.test.js` → regex) ∩ `summary.editedFiles` must be empty.
  - Output table (`name result tier tokens duration`) + summary block (pass count, per-tier counts, total tokens, skipped noted as "LLM cases skipped"). `--json` prints machine-readable JSON instead.
  - Exit code 1 if any FAIL (SKIP is not a failure).
- [ ] **Step 2:** `npm run build` compiles it to `dist/benchmarks/run.js`.
